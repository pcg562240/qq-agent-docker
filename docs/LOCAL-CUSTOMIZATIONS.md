- 历史 Linux 来源：`prolet1966/QQ-Agent-for-Linux`，`da6f0560c1c7530a985bb4c1542a88cae104b80e`（`upstream-linux-base-20261007`），不再跟进合并该 remote。迁移前回退点 `before-official-migration-20261013`；详见 [迁移记录](OFFICIAL-UPSTREAM-MIGRATION.md)。

- 本地已有两个机器人配置，每次只运行一个；模型服务共用，聊天、记忆、名单、技能和凭据按机器人隔离。用户已确认私聊、加群；近期部署检查显示当前 QQ 已连接。

- 代码备份不等于数据备份：Git 不保存 `.env`、Docker 数据卷、聊天记录、模型密钥、截图原稿、权重或运行日志。

### L01 Docker 运行时和环境隔离

**文件**：`Dockerfile`、`compose.yaml`、`.dockerignore`、`.env.example`、`scripts/docker-init.mjs`、`src/docker-server.js`、`src/docker-env.js`、`src/server.js`、`src/app.js`、`skills/image-generate/index.js`。

- 在导入配置/应用之前选定机器人目录；环境覆盖不回写密钥，初始化已有 `.env` 时不覆盖密码。
- Docker 不自动启动桌面 QQ/SnowLuma/MongoDB，不后台同步社区名单或价格表，不在启动时预热免费图片模型；用户主动操作仍按能力和配置执行。
- 默认只监听宿主回环；不把宿主程序、权重、私人配置或 `node_modules` 打入源码提交。

**测试**：`docker-channel`、`docker-http`、`docker-console-network`；容器 UID、只读根、卷和健康检查另做部署验收。

### L03 局域网控制台和连接诊断

**文件**：`src/console-auth.js`、`src/app.js`、`src/docker-env.js`、`src/qqbot.js`、`ui/login.*`、`ui/connection.*`、`compose.yaml`。

- 局域网需显式设置绑定地址、精确 Host/端口名单以及控制台密码；保留登录、API/SSE 鉴权、HttpOnly/SameSite Cookie、同源检查。
- 控制台接受显式自定的 8–256 位安全字符密码，仍建议至少 24 位随机密码；初始化继续生成 64 位随机十六进制密码。改密只更新私有 `.env`，重建服务容器加载环境，旧 Cookie/请求密钥失效，不改机器人配置或数据卷；实际密码不得进入代码、测试或文档。
- 不信任任意转发头，不用通配 Host，不因开放 LAN 放开 QQ 群白名单。
- 保留腾讯 `/gateway` 返回的具体错误。腾讯源 IP 白名单、控制台 Host 名单、允许聊天 OpenID 名单是三个不同机制。

**测试**：`docker-console-network`、`docker-http`、`docker-channel`。

### L10 引用图片进入模型和可见答复

**文件**：`src/qqbot-quotes.js`、`src/message-quotes.js`、`src/reply-completion.js`、`src/qqbot.js`、`src/app.js`、`src/store.js`、`src/prompt.js`、`src/tools.js`、`src/orchestrator.js`。

- 解析 QQ 引用 `msgElements` 中的文字/附件；引用媒体与当前消息媒体分开持久化，缓存按会话隔离，优先新推送地址。
- `get_message_detail` 返回引用信息/图片数；`get_message_images` 合并当前图与引用图、去重，并仅追溯同会话一跳。
- **2026-10-13 长消息 ID 防改写**：实际存档有图，但模型把 137 字符的协议 ID 改写成 86 字符后首次查询失败。新增 `src/message-reference.js`：长度 ≥64 的 ID 在提示词、历史/详情/图片结果和失败提示中显示为 `m序号-校验码`，由聊天 key、本地序号和原始 ID 确定，缓存/重启后稳定；只用于模型交互，存档及 QQ 协议 ID 不变，无数据迁移。
- 统一工具入口精确还原 `messageId` / `message_id` / `replyToMessageId` 及绘图 `references[].message_id` / `mask.message_id`，适用于内置工具和已安装 ComfyUI/ChatGPT 生图扩展，无须替换外置扩展。保留绘图 `#数字` 本地序号旧语法；不遍历正文、成员 ID、URL 或任务 ID。跨聊天、撤回、裁剪、清空后序号复用但 ID 不同、校验不符均拒绝；不模糊匹配、不回退最新图片。
- 初始/查询后可见答复提醒识别当前触发的短编号，仍受原有次数、发送尝试及轮次边界限制。此修复降低模型复制长 ID 的错误，不承诺模型永不填错参数或一定调用绘图。
- `refMsgIdx` 是引用索引，**不当作能发送的 QQ 消息 ID**；取不到引用明确标 unavailable，请用户重发，不猜新闻内容。
- 本轮直接群 @ 或私聊、尚未发送时，初始提醒覆盖零工具调用结束（包括空正文/只有思考），或查过本条消息后忘记发送。另设一次独立的**查询后发送提醒**，覆盖先消耗初始提醒、再取图/搜索、最后又只思考的情况；两阶段各最多一次，仍受管理员设置的模型轮次上限约束。
- 查询后提醒仅接受已完成且调用 ID/名称匹配的 `web_search` / `web_fetch` 或本条消息的 `get_message_images` / `get_message_detail`；此前有提醒时，必须有该提醒之后的新查询结果，不因连续空结束重复催促。历史图片查询本身不触发，但随后完成联网查询可以触发。查询失败也可提醒模型如实解释限制，不伪造答案、不盲目重搜。
- 普通群闲聊、主动运行、已发送、发送工具关闭及明确 `finish` 均不追加提醒。任何发送尝试（含失败）或白名单外工具/技能调用均排除两种提醒，避免未知副作用变成重复发送；内部思考和普通模型正文绝不能直接当 QQ 回复发送。会话保留 `replyReminderUsed`，另记 `queryReplyReminderUsed` 和 `protocolReminderPhase` 便于区分阶段，不向模型 API 发送这些诊断字段。
