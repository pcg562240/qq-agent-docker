## 结构

```text
QQ 官方 API / Gateway（需要 AppID + AppSecret）
                │ 官方 Node.js SDK，主动出站 WebSocket + HTTPS
                ▼
        src/qqbot.js 适配层
                │ 与原 Agent 所需的小部分 OneBot 方法兼容
                ▼
  入站白名单 → ChatStore → Orchestrator → 模型工具调用
                │                           │
                └──── Sender 队列 ←─────────┘
                            │
                      文字 / 图片回复

浏览器 → 回环 / 显式启用的局域网端口 → Host 与同源校验 → 控制台鉴权 → HTTP API / SSE
                                  │
                                /data 卷
```

另一路通过 `QQ_AGENT_CHANNEL=onebot` 复用原 OneBotClient，接外部网关；两条通道不能在同一实例里同时工作。

## SDK 使用细节

- SDK 的 `start()` 持续到停止，并不是连接就绪 Promise；用 `ready` / `resumed` 事件更新状态，不阻塞 HTTP 启动。
- SDK 管理 token、心跳和 Gateway 重连；当生命周期退出时，适配器再按退避时间重建。旧连接事件通过 generation guard 隔离。
- 订阅 QQ 群/私聊对应的最小 intent，不额外订阅频道。处理 `C2C_MESSAGE_CREATE`、`GROUP_AT_MESSAGE_CREATE`、`GROUP_MESSAGE_CREATE`。
- 本地保留最近消息作为被动回复锚点（保守保留 4 分钟），与显式引用 `messageReference` 区分。这个本地期限不是对平台时效的承诺。
- 显式文字引用只允许同一会话、本进程缓存中仍存在的消息；图片首版不附带引用或 @。
- 已完成入站处理的消息 ID 写入 bounded 去重账本，重启恢复；入站处理失败不提前确认。崩溃恰好落在入库与账本写入之间仍可能重复，未实现事务性的 exactly-once。
- 未在白名单的会话只记录标识/展示名称，不存正文、不调用模型。
- 群名单/好友名单是已发现会话的兼容视图，不冒充平台完整名单。未实现的 OneBot API 明确报错。
- 外部图片用原有 `safeFetchBinary` 限制下载；本地图片只允许数据卷媒体目录，并校验 realpath，避免指向配置/密钥文件的符号链接。原 sender 的跨机 base64 读取回退在官方通道停用，避免绕过此限制。

## 2026-10-11 多机器人配置与切换

### 使用与数据布局

- 「连接设置」新增已保存列表、显示名称、手动新增 / 更新非当前机器人、仅保存 / 保存并切换。当前 AppID 只读，当前 AppSecret 仍可单独更新。QQ 扫码确认其他 AppID 会保存到它的独立空间并切换，不再要求更换整个 Docker 数据卷。
- 同一进程只运行一个机器人，不实现同时在线；切换会停止旧 QQ 连接与任务，再退出进程，由 Compose 的 `restart: unless-stopped` 拉起新进程。网页轮询健康状态，观察到新的进程标识才刷新。
- `/data/robot-profiles.json` 只保存选中项、名称、AppID 等索引，不含密钥。`/data/shared-models.json` 共用模型 API、提供商与模型密钥；`/data/robots/<AppID>/` 独立保存其余配置、QQ SDK 会话、OpenID、聊天、记忆、提醒、媒体与日志。新机器人不复制旧机器人数据。
- `docker-server.js` 在导入应用前选择数据目录，避免运行中改全局路径导致缓存 / 定时器串号。首次空安装使用禁用 QQ 的 `setup` 空间。
- 旧版先保留原根目录并复制到 `legacy-backups`，随后迁入当前 AppID 的空间，索引最后提交；不删除旧数据。身份不一致、损坏 JSON、链接 / 特殊文件及未知的已存在目标目录均停止迁移而非覆盖。配置写入使用临时文件、fsync、rename，密钥文件权限 0600。
- `.env` QQ 凭据非空时禁止页面多机器人管理，需由用户清空环境覆盖并重建后再配置；不自动把环境秘密写入磁盘。旧版「整体重置数据」在多机器人模式下阻止执行，聊天 / 记忆分项清理仍可使用。

### 接口与保护

- `GET /api/robots` 返回当前 AppID、脱敏列表及进程 `context`；`POST /api/robots/save` 保存 `{appId, appSecret?, name?, activate?}`；`POST /api/robots/switch` 接受 `{appId}`。环境管理、非法 ID、路径穿越与身份冲突会被拒绝。
- 所有 HTML 注入当前进程标识，fetch / SSE 自动携带上下文；旧标签页在切换后收到 409，不能把旧表单写到新机器人。API 客户端也需在写操作携带 `X-QQ-Profile-Context`，SSE 可用 `profileContext` 参数。
- 控制台密码、Host 白名单与同源保护保留；切换期间拒绝新的 API 操作。密钥不出现在列表、二维码状态和日志中。
