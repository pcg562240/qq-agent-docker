## Git 迁移方法

1. 给旧 main 固定回退标签，不删除旧历史、不触碰运行卷。
2. 从官方真实 commit 创建独立 worktree/集成分支，使官方 commit 成为新分支的祖先。
3. 只读取旧交付提交中的**已跟踪 Git blob**迁入下游补丁，不复制本机工作目录、`.env`、日志、数据或 node_modules。没有下载上游压缩包覆盖生产目录。
4. 核心调度、提示词、存储、工具接口以官方版本合入旧基线到本地版本之间的差异，逐项解决冲突；平台/控制台仍承接必要的兼容层，纳入差异清单。不是只把 remote 改名，也不是以 `--allow-unrelated-histories` 拼接两套历史。
5. `docs/upstream-source.json` 记录官方每个文件的 blob 和有意保留的覆盖层。旧 Linux 打包脚本及交接文档保留为历史资料，不再作为拉取上游的入口，也不进入 Docker 运行层。

旧历史仍用于证明平台移植和本地补丁的来源，但不再向新主线合并 `upstream-linux/main`。新主线可直接与 `upstream-official/main` 做三方合并。

## 已合入的官方核心行为

- **触发调度**：按单条消息判断，未触发消息标已读；触发后固定聚批窗口，不被后来闲聊反复延长；运行期间的积压在结束后逐条补判定。
- **精确 @ 标记**：OneBot 消息段按成员 ID 判定，避免同昵称误唤醒和他人昵称里的关键词误触发。官方 QQ Gateway 的明确 `officialAtMe` 标记优先，不退回纯文本猜测。
- **提示词锚点**：官方的「已读信息／新已读信息／未读信息」结构与有界前缀复用；保留本地完整 OpenID、引用图、多人路由指引和直接召唤提醒。原先的「本次唤醒／过去状态」标题不再是解析接口。
- **内置思考适配**：保留 `src/thinking.js`，无需扩展也可处理请求参数、返回 reasoning 和被拒参数降级。已有生效的 `thinking-adapters` 优先保留其参数配置；usage 只算一次；普通 400 不因思考适配额外重试。未改动用户模型配置。
- **扩展设置与图片权限**：保留官方的 Cookie/Key 和数组账号密钥脱敏，同时补齐写入侧的掩码保留（按稳定账号 ID，不按数组位置；服务地址改变时不继承旧 Key）。继续保留现有发网图/搜图的显式开启条件，不因迁移放开权限。
- **日志与工具加载**：官方批量落盘、停机 flush；插件日志保留格式串插值。保留 Docker 外置模块路径、可写安装、模型目录扩展点和严格工具 schema。

本地缓存预热功能保留为显式配置能力，没有自动开启；官方提示词锚点不需要额外模型请求。构造请求的 `buildOnly` 分支及时清理超时计时器。

## 下游维护层

- Docker：非 root、只读应用目录、LAN 鉴权、数据卷隔离、显式部署/回滚、禁止启动桌面 QQ 和后台默认预热。
- 官方 QQ：扫码、多机器人配置、Opaque ID、引用图片、固定被动回复锚点、入队时绑定目标、已有 @ 模式及隐私诊断。
- 控制台：多模型 Key 隔离、目录获取/文本连通测试、群备注、旧页面上下文保护、看板原因提示、图标。
- 扩展：见 [独立扩展维护](extensions/README.md)。沿用安装布局以免破坏相对导入；**同仓库不等于跟随核心覆盖更新**。

保护项 L01–L20 原样保留，L21 记录本次上游迁移。机器检查不能代替行为回归。

## 测试与已知限制

必须通过 `audit:local`、`audit:public`、`test:local`，以及隔离 Linux 容器中的 `test:platform`、`test:upstream` 和镜像启动 smoke。`test:upstream` 是选定的离线核心回归，不是所有桌面/安装器测试；未宣称 Windows Electron 客户端、真实 QQ 或全部市场扩展通过实测。

适配上游调度测试时，保留所有触发/积压断言，只把模拟模型设为明确调用 `finish`，避免把本地「未发送提醒」增加的一轮误算为重复调度；慢速脚本按实际请求索引设置；测试 harness 显式使用 Docker 启动保护、本地 OneBot/模型替身和鉴权，禁止桌面程序启动与默认网络预热。旧 Docker 测试仅更新提示词段名定位，不删除路由、可见回复或边界断言。

此前扩展审计发现的能力调用方式、占位实现、OpenID 兼容和重复 ID 等问题不会仅凭更换上游消失，本次没有把它们标为已修复，也不自动禁用/替换运行扩展。详见扩展维护文档。
