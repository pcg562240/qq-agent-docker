# QQ-Agent Linux 构建方案

> 目标：把 QQ-Agent V0.4.4（Windows Electron 应用）交付为 Linux 三个安装包
> —— Debian 系 `.deb`、RPM 系 `.rpm`、通用版 AppImage。

---

## 1. 总体架构

### 1.1 原版（Windows）是什么样

```
QQ Agent v0.4 setup.exe  (NSIS 安装包, 188 MB)
└── E:\Program Files\QQ Agent\QQ Agent v0.4 setup\
    ├── QQ Agent v0.4 setup.exe   ← Chromium/Electron 主程序
    ├── resources/app/            ← 应用代码（asar 关闭，明文目录）
    │   ├── electron/main.js      ← 主进程
    │   ├── src/                  ← 40 个模块（agent 核心）
    │   ├── ui/                   ← 控制台前端
    │   ├── plugins/ skills/      ← 插件与技能
    │   └── snowluma/             ← ★ 协议端（295 MB，Windows 原生二进制）
    ├── data/                     ← 运行期数据（config/记忆/会话）
    └── *.dll, *.pak              ← Electron 运行时
```

进程模型：**Electron 主进程 → 拉起 SnowLuma（node.exe index.mjs）→ SnowLuma 注入 Windows QQ**

### 1.2 Linux 版目标形态

```
/opt/qq-agent/                        ← 程序（root 所有，只读）
├── qq-agent                          ← Electron 主程序（重命名自 electron）
├── resources/app/                    ← 同一份应用代码 + Linux 补丁
│   └── snowluma/                     ← SnowLuma **Linux x64** 原生版
└── *.so, *.pak                       ← Electron Linux 运行时

~/.local/share/qq-agent/data/         ← ★ 运行期数据（遵循 XDG，用户可写）
~/.config/qq-agent/snowluma/          ← ★ SnowLuma 配置（用户可写）

/usr/bin/qq-agent                     ← 启动器（shell）
/usr/share/applications/qq-agent.desktop
/usr/share/icons/hicolor/*/apps/qq-agent.png
```

**两个 ★ 是本方案的核心设计**：原版把数据放在安装目录里，在 Windows 上勉强能用
（安装目录 ACL 允许写入），**在 Linux 上会直接失败**——`/opt` 属 root。
必须把「程序」与「数据」彻底分开。

## 2. 关键技术决策

### 2.1 为什么用 Electron 官方 Linux 运行时，而不是 electron-builder 交叉构建

| 方案 | 评估 |
|---|---|
| `electron-builder --linux deb rpm` 在 Windows 上跑 | ⚠️ 交叉构建 Linux 目标在 electron-builder 里路径复杂，且需要外部 `fpm`/`app-builder` 二进制；出错难排查 |
| **在 WSL 里组装 + 用原生 `dpkg-deb` / `rpmbuild` 打包** | ✅ **选用**。工具都是发行版原生的，产物可信；且 WSL 就是真实 Linux，能直接装、直接跑测试 |

代价：需要手工维护安装目录树和元数据（`control` / `.spec`）。
收益：完全可控、可复现、可验证，不依赖任何不确定的跨平台工具链。

### 2.2 数据目录：`QQ_AGENT_DATA_DIR` 环境变量优先 + 补丁兜底

`electron/main.js` 的 `resolveDataDir()` 原本优先级是：
```
QQ_AGENT_DATA_DIR 环境变量  >  exe 同级 data/
```

两种改法：
- **(A) 只在启动器里设 `QQ_AGENT_DATA_DIR`** —— 零代码改动，但用户直接跑
  `/opt/qq-agent/qq-agent`（不经启动器）时会回落成写 `/opt`，静默失败
- **(B) 打补丁让 Linux 分支自己算 XDG 路径** —— 任何入口都对

✅ **两者都做**（补丁 + 启动器兜底）。补丁保证正确，启动器保证可见可调。

### 2.3 SnowLuma 版本选择

原版内置 **v1.14.13**；官方最新 **v1.14.19**。

选用 **v1.14.19**（官方最新稳定版），理由：
- 官方 release 明确写"跨平台正式支持：Windows x64、Linux x64 与 Linux arm64 均可完整运行"
- 用最新版可吃到 Linux 侧的修复
- 风险：比原版高 6 个小版本，**OneBot 协议面理论上兼容**，但需实测验证
  （冒烟测试里要覆盖 OneBot WS 3001 端口就绪）

若实测发现 v1.14.19 与原版 app 代码不兼容，**回退方案**是用 v1.14.13 的 Linux 包
（同 tag 有 `SnowLuma-v1.14.13-linux-x64.tar.gz`），保持与原版完全同版本。

### 2.4 完整版 vs Lite 版 SnowLuma

| | 完整版 | Lite 版 |
|---|---|---|
| 大小 | 46.4 MB | 4.1 MB |
| 自带 Node | ✅ | ❌ 需系统 node `^22.13 \|\| >=23.4` |

✅ **选完整版**。自带运行时 = 不依赖用户系统 node 版本，少一类安装失败原因。
`src/app.js` 的补丁已同时支持「自带 node」和「系统 node」两条路。

## 3. 打包设计

### 3.1 安装布局（FHS 合规）

| 内容 | 路径 | 权限 |
|---|---|---|
| 程序本体 | `/opt/qq-agent/` | root:root，目录 755，可执行文件 755 |
| Chromium 沙箱 | `/opt/qq-agent/chrome-sandbox` | **root:root 4755**（setuid） |
| 启动器 | `/usr/bin/qq-agent` → `/opt/qq-agent/qq-agent` | 755 |
| 桌面项 | `/usr/share/applications/qq-agent.desktop` | 644 |
| 图标 | `/usr/share/icons/hicolor/{16,32,48,64,128,256,512}x*/apps/qq-agent.png` | 644 |
| 元数据 | `/usr/share/metainfo/qq-agent.appdata.xml`（可选） | 644 |

**关于 `chrome-sandbox`**：Electron 默认启用 Chromium 沙箱，要求
`chrome-sandbox` 是 setuid root。两个选择：
- 保留沙箱（安全，推荐）：包内 4755，且**必须**在 postinst 里再 `chmod 4755` 一次
  （有些打包工具会丢掉 setuid 位）
- 放弃沙箱：启动器加 `--no-sandbox`（**不推荐**，会降低安全性）

✅ 选**保留沙箱**，postinst/posttrans 里补 `chmod 4755`。

### 3.2 运行时依赖

**Debian/Ubuntu**（Electron 33 所需共享库）：
```
libgtk-3-0, libnotify4, libnss3, libxss1, libxtst6, xdg-utils,
libatspi2.0-0, libuuid1, libsecret-1-0, libasound2 | libasound2t64
```
> ⚠️ `libasound2t64`：Debian 13 / Ubuntu 24.04+ 改名了。**必须写成
> `libasound2 | libasound2t64` 的备选形式**，否则新老系统有一边装不上。

**RHEL/Fedora**（名称映射，RPM 系没有 `lib` 前缀习惯）：
```
gtk3, libnotify, nss, libXScrnSaver, libXtst, xdg-utils,
at-spi2-atk, libuuid, libsecret, alsa-lib
```

### 3.3 启动器脚本设计

`/usr/bin/qq-agent` 是 shell 脚本（不是直接指向二进制），职责：
1. 计算并 `export QQ_AGENT_DATA_DIR`（XDG 规范）
2. 建目录、纠正 chrome-sandbox 权限（若被意外改动）
3. 处理 Wayland/X11 兼容（`--ozone-platform-hint=auto`）
4. 中文 locale 兜底
5. `exec` 主程序（`exec` 保证信号正确传递、不留多余 shell 进程）

> AppImage 版**复用同一个启动器**，只是路径改为 `$APPDIR` 相对，数据目录同理指向
> 用户主目录（AppImage 的 `$APPDIR` 是只读挂载点，绝不能往里写）。

### 3.4 三个包的差异

| | .deb | .rpm | AppImage |
|---|---|---|---|
| 安装位置 | `/opt/qq-agent` | `/opt/qq-agent` | 单文件，挂载到 `$APPDIR` |
| 依赖处理 | `Depends:` 字段 | `Requires:` 字段 | 无（自带运行时，仍依赖系统库） |
| setuid 沙箱 | postinst 处理 | `%post` 处理 | **不可用**（FUSE 挂载无法保留 setuid）→ AppImage 版启动器需 `--no-sandbox` 或检测降级 |
| 卸载 | `dpkg -r` | `rpm -e` | 删文件即可 |
| 数据目录 | `~/.local/share/qq-agent` | 同左 | 同左 |

> ⚠️ **AppImage 的 setuid 限制**是真问题：SquashFS 挂载不保留 setuid 位。
> 方案：AppImage 启动器检测沙箱不可用 → 加 `--no-sandbox`，并在 README 里如实说明
> 这是 AppImage 形态的固有限制。

## 4. 构建流程（每步可独立重跑）

```
01-extract.sh      下载/解包 Electron + SnowLuma             [已可用]
02-test-patch.sh   验证补丁（副本试跑）                        [已可用]
03-stage.sh        组装 stage/opt/qq-agent 完整树             [待写]
04-build-deb.sh    → out/qq-agent_0.4.4_amd64.deb             [待写]
05-build-rpm.sh    → out/qq-agent-0.4.4-1.x86_64.rpm          [待写]
06-build-appimage.sh → out/QQ-Agent-0.4.4-x86_64.AppImage     [待写]

test/10-deb-smoke.sh    dpkg -i 真实安装 + xvfb 启动冒烟       [待写]
test/20-rpm-smoke.sh    rpm -i  真实安装 + xvfb 启动冒烟       [待写]
test/30-appimage-smoke.sh                                   [待写]
```

**stage 阶段的可重跑性**：`03-stage.sh` 每次都从 `E:\` 原始树**重新复制**再打补丁，
不在上一轮产物上叠加。这样保证「补丁基准永远是干净的 V0.4.4」。

## 5. 冒烟测试设计（验收标准）

用户要求"测试无误"。定义为以下**全部通过**：

| # | 检查项 | 判据 |
|---|---|---|
| 1 | 包能装上 | `dpkg -i` / `rpm -i` 退出码 0，无未满足依赖 |
| 2 | 文件就位 | `/opt/qq-agent/qq-agent` 存在且可执行；`.desktop` 通过 `desktop-file-validate` |
| 3 | **数据目录落在用户主目录** | 启动后 `~/.local/share/qq-agent/data/config.json` 存在；`/opt/qq-agent/data` **不存在** |
| 4 | 主进程能起来 | `xvfb-run qq-agent` 启动后进程存活 > 15 秒，不秒退 |
| 5 | **控制台监听 3210** | `TcpClient` 探 `127.0.0.1:3210` 通 |
| 6 | HTTP API 正常 | `GET /api/config` 返回 200 且是合法 JSON |
| 7 | 单实例锁生效 | 启第二个实例，被拦下且不产生第二份数据 |
| 8 | SnowLuma 能拉起 | `POST /api/snowluma/launch` 后，WebUI 端口 5099 就绪 |
| 9 | OneBot 客户端在跑 | 日志出现 OneBot（SnowLuma）连接尝试，无崩溃 |
| 10 | 卸载干净（数据保留） | `dpkg -r` 后 `/opt/qq-agent` 移除，`~/.local/share/qq-agent` **保留** |
| 11 | 中文不乱码 | 控制台 HTML/JSON 中文正常（检查 `Content-Type: charset=utf-8`） |
| 12 | 无残留 Windows 调用 | 日志中没有 `wmic`/`taskkill`/`explorer.exe` 相关报错 |

> 判据纪律：**一律用端口探测判活跃，不用 `ps`/进程名**。
> 本项目交接文档明确记载过"沙箱里 `Get-Process`/`tasklist` 不可靠，会返回 0 让人误判"。

## 6. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| SnowLuma 要真实 Linux QQ + 注入，包装上也不能直接用 | **高** | 如实告知，不假装开箱即用；README + 安装后提示写明前置步骤 |
| SnowLuma 配置目录写不进去（`/opt` 只读） | **高** | stage 阶段必须解决（见交接文档 §5 待办） |
| v1.14.19 与 app 代码不兼容 | 中 | 回退 v1.14.13（同版本），有明确回退路径 |
| AppImage 无 setuid → 沙箱不可用 | **确定** | 启动器降级 `--no-sandbox` 并说明 |
| 依赖名在新老发行版不同 | 中 | deb 用 `a \| b` 备选；rpm 独立映射表 |
| xvfb 下 GPU 相关崩溃 | 中 | 启动器/测试加 `--disable-gpu`（仅测试用） |
| Electron 在无 X 环境直接失败 | 确定 | 测试一律走 `xvfb-run` |
