**从 Windows 调 WSL 的纪律（重要，我踩过）**：
> 用过长的内联 bash 时，PowerShell 会把引号和 `$(...)` 吃掉，`for` 循环直接语法报错，

### 4.3 Linux 适配补丁（9 处，已验证）

全部在 `patches/patch-linux.mjs`。补丁针对 **stage 副本**，**从不修改** `E:\` 上的原始安装。

| # | 文件 | 补丁 ID | 解决的问题 |
|---|---|---|---|
| 1 | `electron/main.js` | `data-dir-xdg` | 数据目录原本落在安装目录（Linux 上是 root 只读的 `/opt`），改到 `~/.local/share/qq-agent/` |
| 2 | `src/app.js` | `snowluma-stop-posix` | `wmic` 停止进程 → `/proc` 扫描 + `process.kill` |
| 3 | `src/app.js` | `snowluma-launch-posix` | 只认 `node.exe` → Linux 认自带的 `node` 或系统 node |
| 4 | `src/app.js` | `snowluma-launch-node-bin` | 给自带 node 补执行位 |
| 5 | `src/routes.js` | `routes-open-data-dir` | `explorer.exe` → `openWith()` |
| 6 | `src/routes.js` | `routes-open-snowluma-dir` | 同上 |
| 7 | `src/routes.js` | `routes-open-webui` | `cmd /c start` → `openWith()` 走 `xdg-open` |
| 8 | `src/routes.js` | `routes-openwith-helper` | 注入跨平台 `openWith()` 帮助函数 |
| 9 | `src/app.js` | `portable-qq-unsupported` | 便携 QQ 是 Windows 专属，Linux 明确返回"不适用" |

**补丁工具的 4 条纪律**（继承本项目历史教训，改动前务必遵守）：
1. 锚点必须**恰好命中 1 次**，0 次或 ≥2 次都**报错中止**——绝不静默跳过
2. 幂等判据**按补丁独立给出**（字符串数组或断言），不能多个补丁共享一个标记
3. 每个文件打完立刻 `node --check`
4. **行尾归一化**：Windows 侧文件全是 CRLF，锚点是 LF，必须归一化后比对、写回时恢复原行尾

## 7. 红线与安全注意

| 项 | 说明 |
|---|---|
| **`community.key` 绝不能打进包** | 该文件的源码注释原文：*"这份密钥只给管理员本机用，绝不能打进分发给别人的安装包。"* 它是厂商云端名单的**写权限**密钥。已核实原版安装包**未**包含它，新包也必须排除（`lib.sh` 的 `EXCLUDE_PATTERNS` 已带上）。 |
| **★ `snowluma/` 下混着用户隐私数据，必须排除** | 实测确认已安装的 app 树里有：`snowluma/data/<QQ号>/`（`messages.db` **私聊消息库**、`media.db`、`snowluma_identity.db` **登录态**）、`snowluma/config/`（WebUI 令牌）、`snowluma/logs/`（含 QQ 号群号消息片段）。**照原样打包 = 把号主隐私和登录态分发出去。** 排除清单已写进 `scripts/lib.sh` 的 `EXCLUDE_PATTERNS`，编制 `03-stage.sh` 时**必须**套用。 |
| **同理排除 `data/`** | 控制台数据含 `config.json`（**API Key 明文**）、sessions、memory-v2、messages。原版 `build.files` 里也是排除的。 |
| **Windows 原始安装不要动** | 所有补丁只作用于 `stage/` 副本。`E:\Program Files\QQ Agent\` 是在跑的线上机器人程序。 |
| **不要杀 SnowLuma** | 若线上机器人的 SnowLuma 在跑，它持有 QQ 登录态。本工程只操作 Linux 侧，不碰 Windows 进程。 |
| **SnowLuma 授权** | 源码可见**非商业**许可，个人自用免费、无需授权码；**商业使用需书面授权**。原生模块（Linux 上是 `.so`）是专有组件，禁止逆向。分发安装包前需确认用途合规。 |
| **AppImage 必须最后做** | 用户明确要求"两版测试无误后再编写通用版 AppImage"。不要抢先做。 |

## 8. 已知开放问题（接手时先解决这些）

1. ~~**SnowLuma 配置目录重定向机制未确认**~~ —— ✅ **已于 2026-09-27 解决**，见
   `05-arm64方案.md` §1.4。结论：`config/` 与 `data/` 是**纯 cwd 相对路径且无环境变量可覆盖**，
   原生件则按 `import.meta.url` 模块相对解析；对策是把 `snowlumaDir()` 指向用户主目录下的
   **符号链接镜像目录**（已实现为第 10 个补丁 `snowluma-runtime-mirror`，锚点 10/10 已验证）。
   > ⚠️ 注意：本节原先猜测的 `SNOWLUMA_CONFIG_DIR` 环境变量**并不存在**——
   > 已实测确认 SnowLuma 没有任何 CONFIG_DIR / DATA_DIR 类变量，别再去文档里找了。
2. **SnowLuma 在 Linux 上需要真实 Linux QQ 进程 + 注入**（官方自述）。
   这意味着：`snowluma/` 目录装进 `/opt` 后，用户**还需要自备 Linux QQ 并扫码登录**。
   → 需要在包的 README / 安装后提示里**如实说明**，不能假装装上就能用。
   这**不影响**打包计划的可行性（应用本体、控制台、OneBot 客户端都照常工作），
   只影响"开箱即用"的预期管理。
3. **`ptrace_scope`**：部分内核默认 `ptrace_scope=3` 会让注入直接被拒。安装后需检测并提示。
4. **`libasound2t64` vs `libasound2`**：Debian 13/Ubuntu 24.04+ 是 `libasound2t64`，
   老版本是 `libasound2`。deb 依赖需要做 fallback（`libasound2 | libasound2t64`）。
5. **rpm 依赖名与 deb 不同**（如 `gtk3`/`nss`/`libXScrnSaver`），需要在 `05-build-rpm.sh` 里做映射表。
6. **多显示器 / 中文输入法**在 xvfb 冒烟测试里覆盖不到，属已知测试盲区，需如实写进测试报告。
