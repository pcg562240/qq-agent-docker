# ChatGPT 生图与搜索（chatgpt2api）

本接入针对 `pcg562240/chatgpt2api` 的 `1.8.1-pcg.2` API（2026-10-13 本地代码核对），不是 OpenAI 官方 API 客户端。
无需修改 QQ Agent 的主聊天模型，不启动 ComfyUI，也不自动切换或禁用现有绘图/搜索技能。

## 安装与页面入口

新版本镜像内置两个**默认关闭**的技能，位于控制台「技能」页：

- **ChatGPT 生图与编辑**：`skills/chatgpt2api-image/`，注册 `draw` 和 `result`。
- **ChatGPT 联网搜索**：`skills/chatgpt2api-search/`，注册 `search`。

按项目扩展规范，二者由 LLM 根据自然语言选择工具，因此属于技能，不是定时/确定性钩子插件。Docker 从镜像加载，文件不会自动热重载；升级代码需重建镜像或使用正确的重载入口。
两个技能各自配置，按当前机器人隔离。未启用时不向模型暴露工具，不后台生成、搜索或刷新模型。

## 连接与模型设置

1. 服务地址填写 **chatgpt2api 的根地址或 `/v1` 地址**。本机 Docker 访问宿主机一般用 `http://host.docker.internal:8030`；容器到该地址不通时填实际可达的局域网地址。Linux Docker 需要 Compose 中已有的 `host-gateway` 映射。
2. 使用 chatgpt2api 的**独立业务用户 API Key**，不是 ChatGPT 网页账号 Token，不借用 QQ Agent 主模型 Key。服务密钥只在后端使用，页面读取为脱敏占位符。
3. 先保存地址/Key，重新打开设置，点击「获取模型列表」。只调用 `GET /v1/models`；不会测试生图/搜索或修改远端目录、默认模型和账号。服务自身可能刷新模型目录/令牌。
4. 从列表选 ID，或直接手填任意有效模型 ID。保留大小写和后缀；不把显示名当 ID，不做隐式别名替换。模型列表只表示候选，不证明账号可用。
5. 刷新失败保留最后成功目录及手填模型；目录按机器人、服务地址、密钥隔离并落盘。换地址而没有明确填新 Key 时清空旧 Key，防止转发给另一个服务。仅根地址与 `/v1` 的等价变化保留 Key。
6. 保存后由管理员选择启用。已有技能不自动关闭；同时启用多个生图技能时，Agent 会结合工具说明选择，可能需要用户明确说“用 ChatGPT 画”。

### 搜索模型的准确含义

此版本 `/v1/search` 的请求只有 `prompt`，后端固定搜索模型。`/v1/responses` 的搜索兼容路径也没有真正将所选模型传给搜索执行器，不能以更换请求中的 model 字段冒充切换搜索引擎。

搜索技能的模型框因此标为 **「可选：搜索结果整理模型 ID」**：
- 留空：仅调用 `/v1/search`，使用其答案与来源。
- 选取/手填模型：先真实搜索，再通过 `/v1/chat/completions`、`stream:false` 让该模型整理资料；多一次文本调用，源链接仍取自原搜索结果。
- 整理失败：保留原搜索结果并注明整理未完成；不偷偷换其他模型或重搜。

未修改 chatgpt2api 源码/固定搜索模型；如未来上游新增真正可选搜索模型接口，需要重新核对并补回归。

## 生图、参考图与编辑

例子（在 QQ 中正常 @ 机器人）：
- “用 ChatGPT 画一张温柔的小鲸鱼头像，512×512。”
- 发送/引用图片：“用 ChatGPT 保留主体，把背景改成海边。”
- 同一会话多图：“参考这两张图做一张新头像。”
- “查询绘图任务 `<任务编号>`。”

`draw` 参数：`prompt`（必填）、`mode=generate|edit`、`count=1..4`、`size`、`quality`、`references` 和可选 `mask`。
每个 reference/mask 只允许 `{message_id, image_index}`，索引从 1 开始。无引用参数时只选本轮唯一带图消息；引用图片支持当前消息和同会话一跳引用，拒绝跨群查找、随意 URL、本机文件路径和多消息时猜图。

编辑模式最多 4 张参考图；PNG 遮罩可以传给接口，但上游对遮罩的遵循程度没有在本轮实测。QQ 参考图先经过核心 SSRF/限量安全下载，再转内联字节上传，不将模型提供的 URL 交给远端代抓。默认单张上限 8 MB，可设 1–20 MB。结果支持 PNG/JPEG/WebP 的文件头识别，不以纯文本成功响应冒充图片。

- `size=auto` 保留上游原尺寸；显式尺寸 1–4096 会由 chatgpt2api 服务端归一化，不宣称原生小图、更短耗时。
- `quality` 是网页提示要求，不宣称已经验证原生质量档位。
- 使用 `/api/image-tasks/generations` 与 `/api/image-tasks/edits`，每个任务一张，多张串行提交。
- 本地先持久化任务编号，再 POST。相同会话同请求去重；超时/提交未确认只查询原任务，不自动重新生成、换模型或调用 resume-poll。
- `result` 查询已创建的当前会话任务，完成后发送。密钥/服务变化时拒绝查询旧任务，避免串身份。
- 下载结果仅接受该服务 `/images/...` 的存储路径，重新基于已配置服务构造下载地址（解决 Docker/宿主 URL 差异）；不跟随重定向、不向结果域名转发 Key，不支持任意外部图床兜底。
- 图片保存到当前机器人 `media/chatgpt2api-image/`，通过现有发送队列/冻结路由发到当前 QQ 会话。不会开启 Markdown、拼接 @ 标签或绕过发送队列。
- QQ 发送失败或进程在发送中退出时，状态是**未确认**，不自动补发/重画。用户确认没收到且要求补发后，使用 `result` 的 `resend_confirmed=true`。
- 停用/重载会中止本地等待，不取消远端已提交工作，不后台自动发图。后来可手动查询。
- 已发送图片/任务最多保留最近 100 项（新建任务前清理）；未确认任务保留用于诊断，累计 1000 个任务文件后阻止新建，请管理员处理历史。不是无限持久化或严格 exactly-once 保证。

## 搜索结果与保密

只从响应取有界 `answer` 和 `sources`，不把完整上游对象、账号邮箱、会话 ID、原始异常发进 QQ/LLM。来源 URL 仅允许无嵌入凭据的 HTTP(S)。外部内容按资料处理，不把网页指令放进系统提示。

空答案且无来源视为失败；有摘要但没有来源时明确标为不可核验。工具不直接发 QQ，由 Agent 整理后调用 `send_message`；已接入现有的一次查询后可见回复提醒，仍保留轮次、已发送、明确 finish 和未知工具限制，不把内部思考直接发送。

## 回归与验收范围

离线专项：`node --test test/docker-chatgpt2api.test.mjs`，纳入 `npm run test:local`。
覆盖参数/模型原样传递、Key 地址绑定、缓存失败与隔离、鉴权/旧页面上下文、UI 手填/获取/切实例、异步提交/查询、引用图/遮罩、多图、去重、未知发送、停用、搜索来源白名单与可选整理。

真实生图和搜索会使用 chatgpt2api 账号额度；不纳入普通测试，不发送真实 QQ 测试消息。离线测试通过不代表模型目录中的全部模型可用，不代表已验证遮罩效果或真实生成速度。

2026-10-13 本轮：Mac/Linux 各 227 项本地回归通过，Linux 平台 35 项通过；隔离浏览器验证了模型获取、下拉选择及手填 ID 保存。只读检查确认运行中的 chatgpt2api 版本为 `1.8.1-pcg.2`，QQ Agent 容器可以访问其 `/v1/models`。未进行真实生图/改图/搜索或 QQ 测试发送，现有运行技能配置保持不变。

## 接入聚合搜索（L20 / 搜索技能 1.1.0）

搜索技能保留独立工具，并新增共享能力 `search.chatgpt2api`；「多引擎搜索聚合」可以选用它，不需要另存一份 Key。支持仅 GPT、并行或普通引擎无链接时备用。聚合只做一次原始搜索，不执行这里可选的整理模型；不开启技能或不在聚合器引擎列表加入 `chatgpt2api` 就不会调用。设置步骤、两个页面入口的区别和验收范围见 [聚合搜索说明](SEARCH-AGGREGATION.md)。

2026-10-13 聚合接入验收：更新后 Mac/Linux 各 244 项回归及 Linux 35 项平台测试通过，已备份并部署本地 Docker。ChatGPT 搜索保持原关闭状态；未进行真实 GPT 搜索或 QQ 测试发送。
