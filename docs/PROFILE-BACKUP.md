# 网页端当前机器人备份／恢复

入口：连接设置页「备份／恢复」，或完整控制台「设置 → 聊天 → 运行节奏 → 当前机器人备份／恢复」。仅 Docker 官方 QQ 多机器人模式，必须先选择已保存的机器人。

## 范围与安全

- 包含当前机器人目录的配置、人设、消息、会话、文件记忆、媒体及已安装技能代码；启用/已配置的自增长 MongoDB 包含集合、BSON 文档与索引。
- 不包含其他机器人、共享模型服务与密钥、实例索引、控制台密码、`.env`、Docker 镜像。迁移到另一实例时，先添加同一 AppID、单独配置共享模型与该机器人的专属 MongoDB。
- `.qqab.gz` 是版本化的 gzip JSONL 私有备份，不是技能 ZIP；文件逐项 SHA-256 校验，数据库使用 BSON 保留类型。**没有加密或数字签名**，校验只检测损坏、不证明来源可信。包含 QQ 凭据/技能密钥与聊天隐私，不能公开上传。
- 技能是可执行代码，恢复后可能由加载器执行。只使用自己或可信来源的备份；上传预览阶段只校验/落暂存文件，不加载技能、不调用模型/QQ、不连接备份提供的数据库地址。
- 容量限制：压缩 512 MiB、解压 2 GiB、单文件 64 MiB、5 万条归档记录（文件、集合、数据库文档等合计）。不支持 MongoDB 特殊集合/视图/集合 options；超过范围请使用完整离线卷备份和 MongoDB 原生备份。

## 导出

点击「生成并导出备份」并确认。正在回复或整理记忆时返回忙碌，不主动打断。任务在正常停机之后、下一次启动聊天服务之前执行；期间机器人/网页短暂离线。完成后页面显示下载入口。

MongoDB 无法连接或发现跨机器人共享数据库时整体失败，不生成悄悄缺库的备份。MongoDB 插件未配置也未启用时不会强制要求数据库。使用仅属于当前机器人的两个 `readWrite` 数据库；不连接管理员库、不导出账号权限。备份是当前时点内容，不补回过去丢弃的消息。

## 导入

1. 选择文件并「上传并预览」，校验格式、完整性、路径与 AppID。
2. 核对文件数、数据库范围，输入当前 AppID，确认可信来源及覆盖。
3. 服务正常停止，重新验证上传文件；先生成操作前的完整回退备份，失败则不改数据。
4. 按当前实例原有连接参数恢复数据库，再替换当前机器人目录；其他机器人、共享模型配置保持原样。数据库范围必须匹配，不从备份连接未知主机。
5. 成功后重新启动。旧 QQ Gateway 会话缓存清除；备份中 waiting/running 会话标记中止，避免自动重放旧回复。

不是跨数据库/文件系统的原子事务：持久化作业记录跟踪阶段；失败恢复操作前数据库及目录。启动入口先处理断电/进程中断后的回退，再校验机器人目录。若回退仍失败，保留数据和备份并停止启动机器人，不能带着半恢复的数据上线；需管理员检查数据库可达性后重启继续回退。

服务器私有目录：`/data/backups/APP_ID/`，独立于当前机器人目录，不递归备份自己。保留最近任务、导出文件和恢复前回退包，不自动删除历史完整备份；定期安全转移并清理不再需要的文件，注意磁盘容量。预览/失败文件同样含私密数据。恢复前还应有管理员级卷备份；网页备份不能替代全部实例灾备。
