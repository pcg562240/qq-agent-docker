# 聚合搜索与 ChatGPT 来源接入（本地 L20）

## 两个页面入口是一条链，不是两个独立引擎

| 页面名称 | 类型 / 目录 | 职责 |
| --- | --- | --- |
| 聚合搜索 | 技能 `skills/search-aggregator-skill` | 向模型注册 `search-aggregator-skill__web_search_agg` |
| 多引擎搜索聚合 | 插件 `plugins/search-aggregator` | 提供 `search.aggregate`，管理引擎、并发、排序、超时和失败状态 |
| ChatGPT 联网搜索 | 技能 `skills/chatgpt2api-search` | 保留独立工具，同时提供 `search.chatgpt2api` 给聚合器复用 |

调用链：模型 → 聚合搜索技能 → 多引擎搜索聚合插件 → 配置的 HTML 引擎 / 已启用的 ChatGPT 搜索能力 → 合并链接与独立摘要 → 模型组织回复并调用 `send_message`。

技能和插件都仍默认关闭，不改已有机器人开关、主模型、名单、密钥或核心 `web_search` 的服务选择。启用聚合不会自动替换所有搜索工具；需要时可向机器人明确说“用聚合搜索”。

## 已确认并修复的问题

1. **默认引擎从未调用**：配置 `bing,so360,baiduWeb,sogou`，函数表却用 `bingHtml,...`；可选调用静默得到 undefined。修复映射，兼容旧 `*Html` 名称，去重配置，未知名称提前报错。
2. **把能力返回值当函数**：技能和检索增强生图在 setup 时调用 `api.capability('search.aggregate')`，得到的是结果 Promise/undefined，不是函数。改为执行时 `await api.capability(name,args)`；支持后续开启、关闭、重载，不在启动时搜索。
3. **“归一化”只 trim、共识可重复计票**：规范化 HTTP(S) URL，去 fragment/常见追踪参数；保留业务查询参数，拒绝嵌入凭据/非网页协议。同一引擎同一链接只计一次，同一引擎配置只执行一次。
4. **页面导航可能混成搜索命中**：不再兜底抓页面所有链接，限定 h2/h3 结果标题，解码 HTML 实体与 Bing 透明跳转。响应最多 2 MiB。网页改版/验证码/解析不到结果仍可能发生，明确为 empty，不承诺“开箱即用”。无法解开的搜索跳转链接保留原链接，不虚构真实目标；不承诺完美跨引擎去重。
5. **无效失败说明 / 未实现的自动回退承诺**：移除“自动退回单引擎”的旧描述。返回各引擎 ok/empty/failed/unavailable/skipped/cancelled 状态，部分故障保留其他成功结果；全部故障不说“没有新闻”。
6. **搜索预算和开关**：网页与 GPT 独立超时，调用方总预算向下传递；停用/重载取消本地等待。聚合搜索与检索增强工具遵守宿主 `requiresSearch` 开关。检索增强生图尊重 `searchTimeoutMs` 和 `searchRewrite`，只产出提示词、不直接画图。

## 怎样使用 GPT 聚合

先在「ChatGPT 联网搜索」设置并保存 chatgpt2api 服务地址和业务 Key，再启用该技能。模型目录获取、手填 ID、地址绑定 Key、机器人隔离都保留。
随后开启「多引擎搜索聚合」插件及「聚合搜索」技能，在插件设置：

| 想要的方式 | 引擎 `engines` | ChatGPT 参与方式 `chatgptMode` |
| --- | --- | --- |
| 只用原网页引擎（默认） | `bing,so360,baiduWeb,sogou` | 无影响，不调用 GPT |
| 只用 GPT | `chatgpt2api` | 两种模式都直接调用一次 GPT |
| GPT + 网页并行 | `bing,so360,baiduWeb,sogou,chatgpt2api` | `parallel` |
| 网页无有效链接时才调用 GPT | `bing,so360,baiduWeb,sogou,chatgpt2api` | `fallback` |

- GPT 每次聚合最多调用一次 `/v1/search`，消耗 chatgpt2api 账号搜索额度；只要普通引擎已有有效链接，fallback 不会调用 GPT。不是质量不足就自动重搜，也不暗中换模型。
- 不复制 Key，不借用主聊天模型凭据。技能关闭、Key 缺失或无能力时，混合模式如实显示 unavailable 并保留网页结果；仅 GPT 模式在插件状态显示需要先配置启用。
- GPT 默认本地等待上限 120000ms，单个网页引擎默认 8000ms，可分别调整。取消等待不是撤销已提交的远端任务，不保证免除服务端用量。
- 聚合只取 GPT 的原始搜索摘要与来源，**不再调用技能可选的整理模型**，避免重复整理。独立 `chatgpt2api-search__search` 仍按原配置执行可选整理。
- GPT 来源链接参与去重/排序，摘要独立展示；没有链接的摘要标注 `hasSources:false`，不伪装成已核实来源或 RRF 命中。多个引擎命中相同链接不是独立事实核验。
- 此版本 chatgpt2api 的 `/v1/search` 仍固定搜索模型；模型选择仅用于独立技能的结果整理，聚合没有增加真正的搜索模型切换能力。

## 复用边界与隐私

- `检索增强生图` 通过同一 `search.aggregate` 使用所选来源，默认总预算仍 5000ms；如果管理员希望等 GPT，需要明确增加预算。其返回提示可交给 ChatGPT 生图工具，但只传工具支持的参数，风格写入 prompt。
- `plugins/kb-growth` 的旧注释提到聚合，但实际仍取内部 `__searchAggregateFn` / 自带 Bing 兜底；本次没有把自动知识入库接入 GPT，避免意外后台消耗和扩大数据写入范围。
- 不访问搜索结果网页正文，不把外部资料当指令；需要抓正文仍走已有 `web_fetch` 的安全下载和浏览锁定。
- 返回有界标题/摘要/来源与状态，不返回原始异常、Key、上游账号字段；不把群消息、密钥或响应写入新运行日志。
- 新增已知只读工具的查询后回复提醒，但仍遵守最多一次、已有发送/finish/未知副作用不提醒的边界，绝不把思考直接发 QQ。
- 仓库原有的嵌套打包副本同步更新并有一致性测试；宿主只扫描一级入口，不新增第二个实例。后装到数据卷的同名副本不会被镜像升级覆盖，需单独评估升级。
